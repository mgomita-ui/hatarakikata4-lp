第0週　はじめに：使い方と、最初の準備（10分）

レリック社会保険労務士法人　AI経営 × クエスト型ブートキャンプ　受講者向け 最終更新：2026年9月6日（「今週の変更点」は配信週に改定します）

このドリルの使い方

  • 毎週月曜の朝に1回分が届きます。 1回15分。同じ回を毎晩15分くり返しても効きます（同じ課題を、違う自社データでもう一度）。
  • 型はいつも同じです。 「頼む → 動かす → 確かめる → 直す」。15分で終わらなければ、そこで止めて「どこで止まったか」を1行だけ記録してください。次の週に効きます。
  • AIは相棒です。 同僚に頼むのと同じで、前提を先に伝え、返ってきたものはたたき台として受け取り、分からない点は聞き返してもらいます。決めるのは、あなたです。
  • 合宿の3つの約束と揃えてあります。
  • ① Claude Code と Codex が、自分のPCで動く（第1・2・3・7・11週）
  • ② MCP で、自社の数字につながる（第5・6・9週）
  • ③ 計算は Codex、文章は Claude。人・AI・専門家の線を引く（第4・8・10・12週）

合宿当日の「反復AIドリル」との関係

  • 当日の午前（11:05〜）にくり返した5つの動き、集める・要約・比べる・洗い出す・分析する を、12週に散らしてあります。集める（第1・5週）／要約（第7週）／比べる（第4・8・12週）／洗い出す（第9・10・11週）／分析する（第6・8週）。当日は練習データ、ここでは自社のデータで同じ動きをします。
  • 午後の出店バトルで AI係数 を上げた5つの記録、「前提を出させた」「比較させた」「リスクを出させた」「聞き返した」「改善に使った」を、各週の最後に「今週のAI係数」として載せています。毎週1つ以上、必ず入ります。
  • 当日と同じで、触った回数がそのまま技になります。読むだけの週を作らないでください。

  1. フォルダに「前提メモ」を置きます。Claude Code は CLAUDE.md、Codex は AGENTS.md という名前のファイルを読んで、毎回の前提にします。中身は最初は3行で十分です。

- 単位：金額は円・税抜。日付は日本時間。

第1週　相棒が動くことを、毎晩確かめる

ねらい

合宿で立ち上げた Claude Code と Codex が、自分のPCでまだ動くことを確かめます。そして「頼む → 動かす → 確かめる → 直す」を、15分の日課にします。今週は、練習用の受注データを AI に作らせるところまで。

15分の手順

時間すること
0〜2分ターミナルで ai-drill に移動し、claude を動かす
2〜8分下のプロンプトで、練習用の受注データ（CSV）を作ってもらう
8〜11分確かめる：できた CSV を Excel で開く。行数・列名・金額の単位を見る
11〜13分直す：気になった点を一つ、言葉で頼んで直してもらう
13〜15分記録：drill_log.md に今日の1行を書かせる

使うプロンプト例

このフォルダに、練習用の受注データを CSV で作って。
列は「受注日, 顧客名, 品目, 数量, 単価, 担当」、30行、直近3か月分。
顧客名と品目は実在しないものにして。
作る前に、前提（金額の単位・税込か税抜か・日付の形式）を先に言ってから作って。

直すとき：

単価は税抜に統一して、右端に「金額」（数量×単価）の列を足して。
直した箇所だけ教えて。

記録するとき：

drill_log.md に「第1週（今日の日付）：受注CSVを作成。（できた／詰まった点を一言）」と1行追記して。

もう片方の相棒でも

同じ最初のプロンプトを codex でも頼んでみてください。返事の仕方、聞き返し方が違います。どちらが自分の言葉に合うか、感触をつかむのが今週の隠れた課題です。

できたかの確認

  • ☐ claude と codex の両方が、自分のPCで動いた
  • ☐ 作る前に「前提」を先に言ってきた（言ってこなければ、次から頼み方に足す）
  • ☐ CSV が Excel で開けて、30行・金額列がある
  • ☐ drill_log.md に1行増えた

第2週　見積3社分のたたき台（バイブコーディング）

ねらい

合宿の「見積3社分：3時間 → 30秒」を、自分のPCでもう一度。日本語で頼んで、動くものを作る（バイブコーディング）の型を体に入れます。返ってきた見積は完成品ではなく、たたき台です。

15分の手順

時間すること
0〜2分ai-drill で claude を動かす。第1週の CSV があることを確かめる
2〜8分下のプロンプトで、見積3社分を Excel で作ってもらう。聞き返しが来たら答える
8〜12分確かめる：3ファイルできたか。1社だけ、合計を電卓で照合する
12〜14分直す：足りない行（有効期限・支払条件）を足してもらう
14〜15分記録：drill_log.md に1行

使うプロンプト例

受注データ.csv の直近1か月から、受注の多い顧客を3社選んで、
それぞれの見積のたたき台を Excel（.xlsx）で3ファイル作って。
項目は「品目・数量・単価・小計・消費税・合計」。単価は CSV の単価を使う。
作る前に、分からない点（消費税率、宛名の形式、有効期限）を先に私に聞き返して。

直すとき：

3ファイルとも、合計の下に「有効期限：発行日から30日」「支払条件：月末締め翌月末払い」の2行を足して。
数字は変えないで。

できたかの確認

  • ☐ 作る前に、AI から聞き返しが来た（来なければ、「先に聞き返して」を CLAUDE.md に足す）
  • ☐ .xlsx が3つできた
  • ☐ 1社分の合計が、電卓の結果と一致した
  • ☐ 「たたき台」として受け取り、自分で確かめた箇所が言える

今週のAI係数：聞き返した（作る前に分からない点を聞き返させる）／前提を出させた

今週の変更点（2026年9月6日時点）

出典：https://support.claude.com/en/articles/12138966-release-notes ／ https://code.claude.com/docs/en/changelog

  • Codex で、返事の一部だけを選んでコピーできるようになりました。 /copy と入力すると、返事全体・コードだけ・引用だけを選ぶ画面が出ます。見積の説明文だけをメールに貼るときに便利です。（Codex CLI 0.150.0、2026年8月26日）

出典：https://developers.openai.com/codex/changelog

第3週　作らせて、確かめて、直す（AI駆動開発）

ねらい

第2週の見積作りを「毎月使える手順」にします。ここでの主役は「確かめる」です。確認の手順そのものを AI に用意させ、わざと壊れたデータを入れて、ちゃんと止まるかを見ます。AI に作らせて、人が確かめて直す（AI駆動開発）の一番小さな形です。

15分の手順

時間すること
0〜2分ai-drill で claude を動かす
2〜7分下のプロンプトで、見積作りを「毎月使える手順（スクリプト）」にし、確認手順も付けてもらう
7〜10分動かす：その手順を実行してもらい、自動の確認が通るのを見る
10〜13分確かめる：CSV に、単価が空欄の行を1行わざと足す。もう一度動かして、どう止まるか見る
13〜15分直す：止まり方が不親切なら直してもらい、drill_log.md に1行

使うプロンプト例

先週作った見積のたたき台を、毎月くり返し使える手順（スクリプト）にして。
実行する前に「確認手順」も作って。少なくとも
・3ファイルの合計が、CSV から計算した合計と一致するか
・単価や数量が空欄の行があれば、そこで止まって行番号を教える
の2つは自動で確かめるように。
まず、どんな作りにするかを3行で先に言ってから作って。

壊して確かめるとき：

受注データ.csv の10行目の単価を空欄にしてから、もう一度実行して。
止まったら、何が原因で、どの行かを私に分かる言葉で表示して。

もう片方の相棒でも

このフォルダのスクリプトを読んで、確認が抜けている点を3つ挙げて。直すのは私が決める。

これを codex に頼みます。作った相棒と、見直す相棒を分けると、抜けが見つかります。

できたかの確認

  • ☐ 「確認手順」が自動で走り、正常なときは通った
  • ☐ 壊れた行を入れたら、行番号つきで止まった
  • ☐ Codex が挙げた「抜け」のうち、直すものを自分で1つ決めた

今週のAI係数：リスクを出させた（壊れた行で止まるか）／改善に使った（Codex の指摘で直す）

今週の変更点（2026年9月6日時点）

  • Codex の会話を、そのまま Markdown に書き出せます。 /export と入力すると、今日のやり取りがファイルになります。「なぜこの作りにしたか」を社員に渡す資料になります。（Codex CLI 0.148.0、2026年8月17日）

出典：https://developers.openai.com/codex/changelog

  • Claude Code で、ファイルを消す操作の安全確認が強くなりました。 rm -rf のような消去命令は、変数経由でも確認が入ります。「作らせて確かめる」の途中で、うっかり消される心配が一段減りました。（Claude Code 2.1.260、2026年9月3日）

出典：https://code.claude.com/docs/en/changelog

第4週　前提を先に言わせ、三通り出させる

ねらい

合宿の「三通りの比較：半日 → 2分」を、自社の判断で使います。今週の題材は「来期の値上げ」。AI に前提を先に言わせ、三通りを表で出させ、最後に決めるのは自分。合宿で「前提を出させた」「比較させた」「聞き返した」が AI係数を上げたのと同じ動きです。

15分の手順

時間すること
0〜2分ai-drill で claude を動かす
2〜7分下のプロンプトで、前提3つ → 三通りの表 → 確認すべき点2つ、の順に出してもらう
7〜10分確かめる：前提3つのうち、自社と違うものを1つ見つけて言い直す
10〜13分直す：前提を直した結果、三通りの数字がどう変わったかを見る
13〜15分決める：自分の判断を drill_log.md に1行（「今回は据え置き。理由は…」）

使うプロンプト例

受注データ.csv をもとに、来期の価格を「据え置き／3%値上げ／5%値上げ」の三通りで比べたい。
まず、この比較に必要な前提を3つ、あなたの仮置きの数字と一緒に先に言って
（例：値上げで失う受注の割合、原価率、単価の丸め方）。
次に、三通りを「売上・粗利・失注リスク」の表にして。
最後に、これはたたき台なので、私が決める前に確認すべき点を2つ挙げて。

前提を直すとき：

前提の2つ目は違う。うちは原価率が55%。それで三通りを作り直して、変わった箇所だけ教えて。

できたかの確認

  • ☐ 前提が、数字つきで先に出てきた
  • ☐ 前提を1つ直したら、表の数字が変わった（変わらなければ、前提が使われていない）
  • ☐ 三通りのどれにするか、自分の言葉で1行書いた

今週のAI係数：前提を出させた／比較させた（三通り）／聞き返した

今週の変更点（2026年9月6日時点）

出典：https://support.claude.com/en/articles/12138966-release-notes

  • Codex が、長いやり取りの途中で自動の「要約」を挟むようになりました。 三通りの比較を何度もやり直すときに、話の流れを保ちます。不要なら設定で tui.auto_recap = false にできます。（Codex CLI 0.153.0、2026年9月3日）

出典：https://developers.openai.com/codex/changelog

第5週　MCP の1本目：自社のフォルダをつなぐ

ねらい

合宿で通した MCP の1本を、自分のPCでもう一度。今週は一番身近な「フォルダ」をつなぎます。AI は渡した情報しか知りません。MCP はその「配線口」です。つながると、ファイルを毎回貼らなくても「先月の上位3顧客は？」に答えてくれます。

15分の手順

時間すること
0〜5分Claude Desktop の「設定 → コネクタ（拡張機能）」で、ローカルフォルダ（Filesystem）を追加し、ai-drill を許可する
5〜9分Claude Desktop のチャットで、下のプロンプト。ファイルを貼らずに答えが返るかを見る
9〜12分確かめる：返ってきた上位3社を、Excel の並べ替えで照合する
12〜14分直す：「どのファイルを読んだか」を先に言わせる形に、頼み方を直す
14〜15分記録：drill_log.md に1行

Claude Code でつなぐ場合は、ターミナルで次を動かします（フォルダの場所は自分のものに）。

claude mcp add drill-files -- npx -y @modelcontextprotocol/server-filesystem ~/Desktop/ai-drill

つながったかは claude の中で /mcp と入力すると一覧で見えます。

使うプロンプト例

ai-drill フォルダの受注データ.csv を読んで、先月の受注金額が多い顧客を上から3社、金額つきで。
読む前に、どのファイルのどの列を使うかを先に言って。

直すとき：

「担当」別にも同じ表を出して。数字の根拠になった行数も添えて。

もう片方の相棒でも

Codex にも同じフォルダをつなげます。

codex mcp add drill-files -- npx -y @modelcontextprotocol/server-filesystem ~/Desktop/ai-drill

できたかの確認

  • ☐ ファイルを貼らずに、フォルダの中身をもとに答えが返った
  • ☐ 上位3社が、Excel の並べ替えと一致した
  • ☐ 「どのファイル・どの列を使ったか」を AI が先に言った

今週のAI係数：前提を出させた（どのファイル・どの列か）

今週の変更点（2026年9月6日時点）

  • MCP の新しい仕様（2026-07-28版）が出ました。 サーバー側が「普通の Web サービスと同じ形」で動かせるようになり、会計・勤怠などの SaaS 各社が MCP を出しやすくなりました。受講者への影響は「つなげる先が増える」こと。お使いの会計ソフトに MCP があるか、Claude Desktop のコネクタ一覧で月に一度見てください。無ければ CSV 書き出し → フォルダ MCP で十分です。（2026年7月28日公開、8月以降に各社対応）

第6週　「先月の粗利は？」に、自社の数字で答える

ねらい

合宿の「粗利の確認：3日 → 一言」を、自社の数字で。今週から実データです。会計ソフトから月次の売上・原価を CSV で書き出し、ai-drill に置きます（顧客名は伏せて構いません）。大事なのは、AI に「粗利の定義」と「どの列を使ったか」を先に言わせること。

15分の手順

時間すること
0〜3分会計ソフトから、先月の「売上」「売上原価」を CSV で書き出し、ai-drill に置く（会計ソフトに MCP があれば、コネクタで直接つないでも可）
3〜7分下のプロンプトで、粗利を一言で答えてもらう。根拠の表つき
7〜10分確かめる：会計ソフトの画面の粗利と照合する。ずれたら、定義か列がずれている
10〜13分直す：自社の粗利の定義を、CLAUDE.md（Codex なら AGENTS.md）に書いてもらう
13〜15分記録：drill_log.md に1行

使うプロンプト例

先月の粗利は？
答える前に、粗利の定義（売上 − 売上原価）と、どのファイルのどの列を使うかを先に言って。
答えは一言。その下に、根拠になる表（売上・原価・粗利・粗利率）を付けて。
定義に迷う点（値引き・返品・運賃の扱い）があれば、私に聞き返して。

定義を残すとき：

いま確定した「うちの粗利の定義」を、CLAUDE.md に3行で追記して。次回から前提として使って。

できたかの確認

  • ☐ 一言の答えの前に、定義と使った列が出た
  • ☐ 会計ソフトの粗利と一致した（一致しない場合、どこがずれたか言える）
  • ☐ 自社の定義が CLAUDE.md または AGENTS.md に残った

今週のAI係数：前提を出させた（粗利の定義）／聞き返した（値引き・返品の扱い）

今週の変更点（2026年9月6日時点）

  • Codex で、MCP の道具ごとに「返してよい量の上限」を決められるようになりました。 会計ソフトから大きな表が返ってくるとき、output_token_limit で絞れます。長い表で会話が埋まるのを防げます。あわせて、MCP のサーバー名に : @ / . が使えるようになりました。（Codex CLI 0.152.0、2026年9月1日）

出典：https://developers.openai.com/codex/changelog

  • Codex で、つなぎ先の MCP が遅くても待つ「猶予時間」を設定できるようになりました。 会計ソフトの応答が遅い朝でも、道具が見つからずに止まることが減ります。（Codex CLI 0.151.0、2026年8月29日）

出典：https://developers.openai.com/codex/changelog

第7週　議事録：会議中に

ねらい

合宿の「議事録：2時間 → 会議中に」を、次の会議で。録音の文字起こし（スマホの録音アプリや会議ツールの文字起こし）を渡し、決定事項・宿題・保留に分けてもらいます。あいまいな箇所には「要確認」の印を付けさせ、聞き返してもらう。会議が終わる前に、議事録が終わっている状態を作ります。

15分の手順

時間すること
0〜2分会議の文字起こしテキストを ai-drill/meeting.txt として置く（無ければ、直近の会議を思い出して10行メモでも可）
2〜7分下のプロンプトで、議事録のたたき台を作ってもらう
7〜11分確かめる：決定事項の数を、自分の記憶と照合。「要確認」の印がある箇所に答える
11〜14分直す：宿題に「担当・期限」が欠けていれば足してもらい、議事録_YYMMDD.md で保存
14〜15分記録：drill_log.md に1行

使うプロンプト例

meeting.txt は今朝の会議の文字起こし。議事録のたたき台を作って。
「決定事項」「宿題（担当・期限）」「保留」の3つに分けて、決定事項だけは箇条書きで。
文字起こしがあいまいで判断できない箇所は「要確認」と印を付けて、私に聞き返して。
先に、会議の目的と参加者をどう読み取ったかを2行で言ってから始めて。

直すとき：

宿題の2つ目、担当は田中、期限は今月末。反映して、議事録_0913.md として保存して。

できたかの確認

  • ☐ 決定事項・宿題・保留の3つに分かれた
  • ☐ 「要確認」の印が付き、聞き返しが来た（来なければ、頼み方に「聞き返して」を足す）
  • ☐ 宿題に担当・期限が全部入った
  • ☐ 次の会議で「会議中に」試す日を決めた

今週のAI係数：聞き返した（要確認の印）／改善に使った（担当・期限の追記）

今週の変更点（2026年9月6日時点）

  • Claude Desktop の Cowork に、Claude 専用のブラウザが付きました。 議事録の宿題に「○○社のサイトで料金を調べる」があれば、そのまま Cowork に頼めます。あなたのブラウザとは別物で、「タブ・ブックマーク・パスワードは Claude からは見えません」。Pro・Max・Team に順次展開。（2026年8月26日）

出典：https://claude.com/blog/cowork-built-in-browser

  • Claude Code で、日時の表記を日本時間・24時間に固定できます。 設定 timeFormat と timeZone。議事録の「期限」を日本時間で揃えたいときに。（Claude Code 2.1.257、2026年9月1日）

出典：https://code.claude.com/docs/en/changelog

第8週　計算は Codex、文章は Claude

ねらい

合宿の3枚目「AI を分けて組み合わせ、三通り出させる」。計算は答えが一つに決まる仕事、文章は読み手で変わる仕事。だから相棒を分けます。Codex に部門別の粗利率を計算させ、その結果を Claude に渡して経営会議向けの報告文にする。最後に、文章の中の数字が Codex の数字と一致するかを確かめます。

15分の手順

時間すること
0〜5分codex で、第6週の CSV から部門別（または顧客別）の粗利率を計算し、gross_margin.csv に書き出してもらう
5〜9分claude で、その CSV を読ませ、経営会議向けの5行の報告文を作ってもらう
9〜12分確かめる：報告文の数字を、gross_margin.csv と1つずつ照合する。数字が変わっていないか
12〜14分三通り：同じ報告文を「社員向け／銀行向け／自分用」で三通り出してもらう
14〜15分記録：drill_log.md に1行

使うプロンプト例

Codex に（計算）：

売上.csv と原価.csv から、部門別の売上・原価・粗利・粗利率を計算して gross_margin.csv に書き出して。
計算式も表示して。数字の丸めは小数1桁。

Claude に（文章）：

gross_margin.csv を読んで、明日の経営会議向けの報告文を5行で。
数字は CSV のまま、1つも変えないで。
最後に「この数字の前提」と「注意点」を1行ずつ。

三通り：

同じ内容を「社員向け（30秒で読める）」「銀行向け（丁寧に）」「自分用（打ち手だけ）」の三通りで。
数字は変えないで。

できたかの確認

  • ☐ Codex の CSV と Claude の文章で、数字が全部一致した（1つでもずれたら、「数字は変えないで」を頼み方に必ず入れる）
  • ☐ 三通りが2分以内に出た
  • ☐ 明日の会議で使う1通りを自分で選んだ

今週のAI係数：比較させた（三通りの文章）／改善に使った（数字の照合）

今週の変更点（2026年9月6日時点）

  • Codex の新モデル GPT-6-Astra が出ました。 「複雑な問題を解く知性と、複数手順の仕事をやり切って、整った文書・表計算・スライドを作る力」をうたっています。Codex は既定でこのモデルになるので、今週の「計算」はそのまま新モデルで動きます。（2026年9月3〜4日）

出典：https://openai.com/products/release-notes/ ／ https://9to5mac.com/2026/09/04/openai-releasing-major-upgrade-to-chatgpt-and-codex-with-gpt-6-astra-details-here/

  • Codex で、古いモデル（GPT-5.4 系）がアカウント連携では選べなくなりました。 /model で選択肢が変わっています。以前のモデル名で設定を固定していた方は、見直してください。（2026年8月31日）

出典：https://developers.openai.com/codex/changelog

第9週　毎朝、勝手に出る納期リスク

ねらい

合宿の「納期リスク：毎朝、勝手に出る」。定型の報告は AI に渡し、人は朝それを見て決める側に回ります。今週は「納期まで7日以内で未出荷」の一覧を、毎朝9時に自動で作る仕組みを作ります。仕組みは AI に作らせ、翌朝ファイルが増えているかを人が確かめます。

15分の手順

時間すること
0〜3分claude で、受注データに「納期」「出荷済み」の2列を足してもらう（練習データで可）
3〜8分下のプロンプトで、リスク一覧を作る手順と、毎朝9時に動かす仕組みを作ってもらう
8〜11分動かす：一度、手で実行して daily_risk.md ができるのを見る
11〜14分直す：並び順の基準（納期が近い順か、金額が大きい順か）を自分の言葉で決めて直す
14〜15分記録：drill_log.md に1行。翌朝9時5分に確かめる予定を手帳に

使うプロンプト例

受注データ.csv から「納期まで7日以内で、出荷済みでない案件」を一覧にする手順を作って。
並びは納期が近い順、次に金額が大きい順。
結果は daily_risk.md に、日付つきで上に追記する形で。
これを毎朝9時に自動で動かしたい。Claude Code の定期実行（/schedule）で組める？
無理なら、Windows のタスクスケジューラで動かす手順を教えて。作る前に、作りを3行で先に。

直すとき：

並び順を「金額が大きい順、次に納期が近い順」に変えて。理由：まず大口を守りたい。

できたかの確認

  • ☐ 手で実行して、daily_risk.md に一覧が出た
  • ☐ 毎朝9時の定期実行が設定できた（Claude Code の /schedule、またはタスクスケジューラで codex exec を回す）
  • ☐ 翌朝、見に行って増えていた（増えていなければ、次の15分でそこを直す）

今週のAI係数：リスクを出させた（納期リスク一覧）／改善に使った（並び順を自分で決めて直す）

今週の変更点（2026年9月6日時点）

出典：https://developers.openai.com/codex/changelog

第10週　人・AI・専門家の三列

ねらい

合宿の3枚目「人がすること・AI がすること・専門家がすることの線が引ける」を、自社の全業務で。AI に棚卸しと仮置きをさせ、迷うものには「？」を付けさせる。人を減らすためではなく、人を人にしかできない仕事に戻すためです。最後に「明日 AI に渡す1つ」を決めます。

15分の手順

時間すること
0〜2分claude を動かす。CLAUDE.md に業種・社員数が入っていることを確かめる
2〜7分下のプロンプトで、業務20個を三列に仮置きしてもらう
7〜11分確かめる：仮置きのうち、自分の実感と違うものを5つ動かす（AI → 人、など）
11〜14分直す：決定版を roles.md に保存。「明日 AI に渡す1つ」に印
14〜15分記録：drill_log.md に1行

使うプロンプト例

うちの業務を20個、部門をまたいで列挙して（CLAUDE.md の業種・規模を前提に）。
それぞれを「AI がする／人がする／専門家がする」の三列に仮置きして、理由を一言ずつ。
迷うものには「？」を付けて。決めるのは私なので、断定しないで。
「専門家」は労務・法務・税務・会計のような、資格や責任が要る仕事。

直すとき：

「請求書の作成」は AI へ、「値引きの決定」は人へ、「就業規則の改定」は専門家へ動かして。
決定版を roles.md に保存して、AI の列から「明日から渡す1つ」を私が選ぶので候補を3つ。

できたかの確認

  • ☐ 20個が三列に分かれ、「？」付きのものがあった
  • ☐ 自分で5つ動かした
  • ☐ roles.md ができ、「明日 AI に渡す1つ」が決まった
  • ☐ 専門家の列にある仕事を、AI にやらせていないか見直した

今週のAI係数：洗い出させて、聞き返した（？印）／前提を出させた（業種・規模）

今週の変更点（2026年9月6日時点）

  • Claude Code に「制限モード」（--restricted）が付きました。 コマンド実行や外部サイトの読み込みを外し、作業フォルダの中のファイルだけを扱う起動方法です。「AI がする」列の仕事を社員に渡すとき、最初はこのモードで渡すと安心です。（Claude Code 2.1.248、2026年8月27日）

出典：https://code.claude.com/docs/en/changelog

  • Claude に、外部のスキル・プラグインを入れる前に安全性を自動で確かめる機能が付きました。 Enterprise プラン向けですが、「他人が作った道具は、入れる前に確かめる」という考え方は全員に当てはまります。（2026年8月6日）

出典：https://support.claude.com/en/articles/12138966-release-notes

第11週　小さなツールを、同僚が使える形に

ねらい

合宿の「自分で、小さなツールを作る。作ったものが翌日の仕事で使える」。第3週の見積スクリプト、または第9週の納期リスクを、AI を使ったことのない同僚が「読んで動かせる」形にします。README 3行、入力ファイルの置き場所、エラーのときの表示。作るのは AI、確かめるのは自分、渡すのは翌日。

15分の手順

時間すること
0〜2分claude で、渡すツールを1つ選ぶ（見積スクリプト or 納期リスク）
2〜7分下のプロンプトで、README・置き場所・エラー表示を整えてもらう
7〜11分確かめる：別のフォルダにコピーし、README だけを見て自分で動かす
11〜14分直す：README で詰まった箇所を直してもらう。Codex に「詰まりそうな点3つ」を予想させる
14〜15分記録：drill_log.md に1行。渡す相手と日を決める

使うプロンプト例

このフォルダの見積スクリプトを、AI を使ったことのない同僚が使える形にして。
① README.md（3行：何ができる・どこにファイルを置く・どう動かす）
② 入力ファイルの置き場所を「input」フォルダに固定
③ エラーのときは、原因と直し方を日本語で1行表示
先に、変える点を箇条書きで言ってから直して。

Codex に（見直し）：

README.md とスクリプトを読んで、初めての人が詰まりそうな点を3つ予想して。直すかは私が決める。

できたかの確認

  • ☐ 別フォルダにコピーして、README だけで動いた
  • ☐ エラー時の表示が日本語で、直し方まで書いてある
  • ☐ 渡す相手と日が決まった（翌日が理想）

今週のAI係数：リスクを出させた（詰まりそうな点3つ）／改善に使った（README を直す）

今週の変更点（2026年9月6日時点）

  • Codex に、プラグインを配布元（マーケットプレイス）から入れる・消すコマンドが付きました。 社内で作った道具を「配る」仕組みの入口です。今は自分のツールをフォルダで渡すだけで十分ですが、社員展開の先にこの形があります。（Codex CLI 0.153.0、2026年9月3日）

出典：https://developers.openai.com/codex/changelog

  • Claude Code に /skill-doctor が付きました。 入れたけれど使っていないスキル（道具）と、それが場所を取っている量を見せてくれます。道具を配る前に、自分の手元を片付けるのに使えます。（Claude Code 2.1.261、2026年9月4日）

出典：https://code.claude.com/docs/en/changelog

第12週　90日の振り返りと、次の90日

ねらい

drill_log.md に11行たまっています。AI に読ませ、「できるようになったこと／まだ詰まっていること／翌朝の経営会議で使えているもの」の三列に分け、次の90日の課題を3つ提案させる。あわせて、合宿で持ち帰った「AI 経営チーム設計図（CMO・CFO・CTO・CIO 4役の定義書）」を、実際に使った90日に合わせて直します。決めるのはあなた。月次1on1に持って来てください。

15分の手順

時間すること
0〜2分claude を動かす。drill_log.md と4役の定義書を ai-drill に置く
2〜7分下のプロンプトで、三列の振り返りと、次の90日の課題3つを出してもらう
7〜10分確かめる：「使えているもの」の列に、本当に会議で使ったものだけが入っているか
10〜14分直す：4役の定義書を、使った役・使わなかった役で直してもらう。たたき台として保存
14〜15分決める：次の90日で最初にやる1つを drill_log.md の最後に1行

使うプロンプト例

drill_log.md を読んで、この90日を三列に分けて。
「できるようになったこと」「まだ詰まっていること」「翌朝の経営会議で実際に使えているもの」。
そのうえで、次の90日の課題を3つ提案して。理由と、15分でできる最初の一歩つきで。
決めるのは私。断定せず、たたき台として。

4役の定義書：

AI経営チーム設計図（4役の定義書）を読んで、この90日で実際に使った役と、使わなかった役を分けて。
使わなかった役は「消す／来期に回す／定義を変える」の三通りで案を出して。
私が決めたら、定義書の改定版を作って。

できたかの確認

  • ☐ 三列の振り返りができ、「使えているもの」が1つ以上あった
  • ☐ 次の90日の最初の一歩を、自分で1つ決めた
  • ☐ 4役の定義書の改定版（たたき台）ができた
  • ☐ 月次1on1に持って行く準備ができた

今週のAI係数：比較させた（三通りの案）／改善に使った（定義書の改定）

今週の変更点（2026年9月6日時点）

  • MCP の次のロードマップが出ました。 柱は「AI が向こうから知らせてくる仕組み（サーバー起点の通知、長い作業の Tasks 拡張）」と「AI の身元を会社として管理する仕組み」。次の90日で、第9週の「毎朝勝手に出る」が「会計側から知らせてくる」に近づいていきます。（2026年8月22日）
