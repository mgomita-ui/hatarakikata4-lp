# 毎週ドリルの運用：金曜に候補を作り、月曜に届け、報告を受け取る

最終更新：2026年9月14日　　主担当：近藤さん　　承認・1on1：五味田さん

毎週ドリル（`bootcamp/drills/`）を12週間まわすための手順です。設計書 §5 を実務に落としました。
読む順：役割 → 毎週の流れ → 本文を直す条件 → 宿題（報告の受け取り方）→ 情報提供 → 代行 → 名簿。

---

## 役割は3つ。配信は近藤さん、承認は五味田さん、正本は原本だけ

| 役割 | 誰 | 持つもの |
|---|---|---|
| 主担当（配信・回収・一次対応） | 近藤さん | 名簿 `recipients.csv`、報告の記録 `log/`、金曜の候補選びと差し替え、月曜の配信、報告への一言。GitHub リポジトリ mgomita-ui/hatarakikata4-lp の collaborator（write）権限。初回に五味田さんが招待し、`git push` が通ることを最初の金曜の前に確かめる |
| 承認・1on1 | 五味田さん | 差し替えの承認（push の前）、月次1on1（15分）、12週後の改定判断 |
| 正本 | 両者 | `drills_12weeks.md`（毎週ドリル）と `../kit/`（当日教材）。直すのはこの2つだけ |

`weekNN.html` は `build_drills.py` が原本から作ります。HTML を直接直しても次の build で消えます。

## 毎週の流れ：金曜に作り、月曜に届ける

| いつ | 何を | 誰が／何で |
|---|---|---|
| 金 9:00 | 候補生成。`tools/weekly_update.py` が4つの出典を取得し、前回以降の新規項目だけを `updates/YYYY-MM-DD.md` に書く（言い換え案・出典URLつき） | 予約タスク。動いていなければ主担当が手動 |
| 金 午前 | 候補から2件を選び、該当週の「今週の変更点」を差し替え → build → 承認 → commit → push | 主担当 → 五味田さん |
| 月 8:00 | 配信下書き。名簿の一人ひとりに、その人の週の HTML を本文にした下書きを作る | 予約タスク。動いていなければ主担当が手動 |
| 月 午前 | 下書きを読んでから、人が送る。送ったら名簿の「現在の週」を +1 | 主担当 |
| 随時 | 報告メール「[ドリル報告] 第N週」を `log/reports.csv` に1行。「詰まった」には2営業日以内（金曜着は火曜まで）に一言 | 主担当 |
| 月次 | 1on1（15分）で `drill_log.md` の三列（できた／詰まった／会議で使えている）を見る | 五味田さん |
| 12週後 | 第12週の振り返りを回収 → 次期に向けて改定 → `git tag drills-vN` | 両者 |

### 金曜：候補から2件を選び、該当週を差し替える

1. `updates/YYYY-MM-DD.md` を開きます。予約タスクが動いていなければ手動で。1〜2分で終わります。
   ```
   python tools/weekly_update.py --date YYYY-MM-DD
   ```
   取得できなかった出典は「取得失敗」と表に出て、残りは続きます。`OPENAI_API_KEY` があれば言い換え案（gpt-6-astra のたたき台）が付き、無ければ空欄です。
2. 該当週を決めます。名簿の「現在の週」+1 が、次の月曜に届く週です。受講者が複数いれば週も複数になります（例：Aさんは第3週、Bさんは第7週）。予約タスクが `updates/YYYY-MM-DD_差し替え案.md` を作っていれば、そこに週ごとの案があります。差し替えるのは、次の月曜に配信する週だけです。日付が4週以上前の週を配信するときは、その週の変更点2件を今週の候補で置き換えます（受講者のいるどの週にも共通の2件でよく、同じ2件を複数の週に貼ってかまいません）。週ごとに別の2件を探しません。
3. 候補から、その週に合うものを2件選びます。選ぶ順は次のとおり。
   - その週の手順で受講者が実際に触る道具・画面・コマンドが変わるもの（最優先。手順が動かなくなるなら臨時配信も。後述）
   - 使い方が広がるもの（新しいコマンド、新しいつなぎ方）
   - 開発者向けの細部（SDK、API の引数、社内ゲートウェイの設定）は落とす
   - 新しい候補が2件に満たない週は、前回の変更点を残して補う。0件なら見出しの日付は変えない（日付は出典の時点）。`CHANGELOG.md` に「YYYY-MM-DD 第N週：新規候補なし、据え置き」と1行。3週続けて0件なら、候補ファイルの取得結果表に「取得できたが項目0件（ページ構造が変わった可能性）」が出ていないか見て、五味田さんに一報
4. `drills_12weeks.md` の該当週「### 今週の変更点（YYYY年M月D日時点）」を書き換えます。型は候補ファイルの末尾にあります（太字の一文＋その週のどこで効くか＋（製品名 バージョン、日付）＋出典URL）。言い換え案はたたき台です。出典と見比べ、原文に無い効果や数字が足されていないか見てから貼ります。
5. 第4・8・12週なら、その下に「この1か月で変わった使い方」を1段落足します（「情報提供」の項）。
6. 冒頭の `最終更新` と、`build_drills.py` の `UPDATED` を同じ日付にします。
7. build します。禁止語 lint に引っかかったら、出た行を直してもう一度。
   ```
   python build_drills.py
   ```
8. `CHANGELOG.md` に1行（日付・第N週・何を差し替えたか）。
9. `git add` → `git commit -m "第N週の変更点を YYYY-MM-DD 時点に"` → 五味田さんに承認を頼む（`git diff` の要点を1〜3行で）→ OK が出たら `git push`。公開先は https://mgomita-ui.github.io/hatarakikata4-lp/bootcamp/drills/ 。反映まで数分。

### 月曜：下書きを読んでから、人が送る

1. `log/outbox/YYYY-MM-DD/` の下書きを開きます（予約タスクが作ります。Gmail の下書きとして作れた場合は Gmail の下書きフォルダ）。無ければ手動で：名簿を見て、ブラウザで `weekNN.html` を開き、全選択→コピー→メール本文に貼ります（書式が残ります）。
2. 冒頭に「先週の詰まりへの答え」が入っていれば読み、名前・社名・固有の数字が消えているか見ます。
3. 送ります。件名は `[ドリル 第N週] （週の題名）`。第1週だけは `week00_intro.html`（はじめに）を同じメールの先頭に貼ります。
4. LINE で受け取りたい受講者（名簿の備考に「LINE」）には、週ページのURL `https://mgomita-ui.github.io/hatarakikata4-lp/bootcamp/drills/weekNN.html` を送ります。金曜の push が済んでいることを先に確かめます。
5. 送ったら、名簿の「現在の週」を +1 にします。12 になった人は配信終了。翌週の月曜に付録「第12週の翌週に送る振り返り依頼」の文面を送り、名簿の備考に「終了 YYYY-MM-DD」を書きます（保持期限の起点）。第12週の振り返り（`drill_log.md` の三列）は、その次の1on1で回収します。

### 随時：報告が来たら log に1行、詰まりには2営業日以内（金曜着は火曜まで）に一言

報告メールの宛先は m.gomita@canvas-sr.jp（`build_drills.py` の `CONTACT`）です。そのままでは近藤さんの受信箱に届きません。初回に一度、五味田さんの Gmail で「件名に [ドリル報告] を含む → ラベル『ドリル報告』を付けて近藤さんへ自動転送」のフィルタを作ります。近藤さん宛に変えるなら `CONTACT` を書き換えて build → push。`../kit/index.html` の「講師に報告」も同じ宛先を直書きしているので、合わせて直します。

週ページの末尾の「今週の報告を送る」ボタンから、件名 `[ドリル報告] 第N週`、本文にチェック内容と1行記録が入ったメールが届きます。

1. `log/reports.csv` に1行足します（無ければ見出し行から作る）。
   ```
   受信日,名前,週,結果,一行,返信日,備考
   2026-10-06,（名前）,3,詰まった,"壊れたCSVで止まらずに進んだ",2026-10-07,次週冒頭で一般化
   ```
   結果は「できた／詰まった／一部」。一行は本文の1行記録をそのまま。顧客名などが入っていたら「（顧客名）」に置き換えてから写します。
2. 「詰まった」には2営業日以内（金曜着は火曜まで）に一言返します（文面は付録）。解決を約束せず、「次の週の冒頭で全員向けに答えます」と書きます。1行の回避策があれば添えます。
3. 同じ詰まりが2件以上重なったら、本文（手順・プロンプト）を直す候補です。`CHANGELOG.md` に「候補：」で1行書き、金曜に五味田さんへ。
4. 報告が無い人には催促しません（返信義務は無い、と最初に約束しています）。

### 月次と12週後：1on1で三列を見て、次期の改定へ

- 月次1on1（15分・オンライン）は五味田さん。受講者の `drill_log.md` を三列（できた／詰まった／会議で使えている）で見ます。`log/reports.csv` のその人の行を前日までに五味田さんへ渡します（名簿ごと渡さない。行だけ）。
- 12週後：第12週の振り返りを回収し、詰まりが重なった週・出典が古くなった週を直します。直し終えたら `git tag drills-vN`（N は期の番号。初期は `drills-v1`）を付けて push します。次期の受講者はそのタグ以降の内容で始めます。

## 本文を直すのは、通らなくなったときと、詰まりが重なったときだけ

- 「今週の変更点」は毎週差し替えます。
- 本文（手順・プロンプト）を直すのは次の2つのときだけです。
  1. 実測で通らなくなったとき（主担当の PC で、その週のプロンプトを一度動かして確かめる）
  2. 受講者の詰まりが2件以上重なったとき
- 直したら `最終更新` と `CHANGELOG.md` に1行。build の禁止語 lint を必ず通します。
- 当日教材（`kit/`）は四半期に1回、`kit/実測.md` を更新して見直します。次回は2026年12月。
- 言い回しの約束（lint が止める語）：AIは「相棒」（部下ではない）。「使いこなす」（使い倒す、は使わない）。「疑う」は使わない → たたき台／聞き返す。「打つ」は使わない → 動かす／頼む。「座る」は使わない。決めるのは人。製品名は Claude Code／Codex／MCP／Claude をそのまま。ChatGPT／Gemini と書かない（GPT-6 Astra は可）。「補助金」と書かない。「自社PCで動くのでデータが社外に出ない」と書かない。見出しはラベルにせず、主張か問いに。

## 受講者の負担は、15分と報告ボタン1回

- 毎週：15分のドリル＋報告ボタン1回（30秒）。報告は「できた／詰まった」と1行。返信義務はありません。
- 詰まった人への返しは、個別の解決ではなく、次の週のメール冒頭に「先週の詰まりへの答え」を1段落入れます。全員向けに一般化します。
  - 消すもの：名前、社名、固有の数字、その人だけの環境の話
  - 残すもの：どこで止まったか、原因として多いもの、同じところで止まったらどうするか（1手）
  - 長さ：3〜4文。手順の書き直しはしない（本文を直す条件は上の項）
- 予約タスク（月曜）は `log/reports.csv` の直近7日の「詰まった」から、この段落のたたき台を作ります。人が読んでから送ります。

## 情報提供は毎週2件。月に1度のまとめと、動かなくなったら臨時

- 毎週：「今週の変更点」2件（出典URLつき）。金曜の項のとおり。
- 第4・8・12週：「この1か月で変わった使い方」を1段落足します。材料は `updates/` の直近4〜5ファイル。変わったことを並べるのではなく、「受講者の使い方がどう変わったか」を一つの流れで書きます（例：「先月までは毎回 `/model` で選んでいたものが、既定が GPT-6 Astra になったので選ぶ手間が消えました。代わりに、結果が前と違うときは前提を聞き返す癖が要ります」）。
- 臨時配信：手順が動かなくなる仕様変更（コマンド名が変わった、画面が無くなった、既定モデルが変わって結果の形が変わる）が起きたら、週を待たずに送ります。
  - 判断：主担当が気づいたらその週のプロンプトを一度動かして確かめ、五味田さんに一報。当日中に配信。
  - 件名：`[臨時] 第N週の手順：〇〇が変わりました`
  - 本文：何が変わったか（1行）／今週はこうする（1〜3行）／週ページも直したこと（URL）／出典
  - 送ったあと、該当週の本文を直して build → push、`CHANGELOG.md` に1行。

## 近藤さんが不在でも、月曜の配信は止めない

代行は五味田さん。最小限は「月曜に届ける」ことです。金曜の差し替えは飛ばしてかまいません。

1. 名簿 `recipients.csv` を開きます（置き場は「名簿」の項）。
2. その人の「現在の週」+1 の `weekNN.html` をブラウザで開き、全選択→コピー→メール本文に貼って送ります。件名は `[ドリル 第N週] （週の題名）`。第1週なら `week00_intro.html` を先頭に。
3. 「今週の変更点」の日付が2週以上前なら、冒頭に「変更点は次週にまとめてお送りします」と1行。
4. 送ったら「現在の週」を +1。
5. 報告メールが来たら `log/reports.csv` に1行。「詰まった」には一言（付録の文面）。近藤さんが戻ったら、その週の `log` を見せて引き継ぎます。

五味田さんが不在で承認が取れないとき：「今週の変更点」だけの差し替えは、主担当の判断で push してよい（案。本文の変更は承認を待つ）。

## 名簿と報告は、リポジトリに入れない

- `recipients.csv` は git 管理外です（`drills/.gitignore` に `recipients.csv`／`updates/state.json`／`log/` を入れてあります）。見本は `recipients.example.csv`（架空1行）。
- 列：`名前,メール,受講日,受講形式,現在の週,備考`
  - 受講形式：訪問・社長1名／訪問・幹部5名まで／会場の回
  - 現在の週：最後に配信した週。`0` は「まだ第1週を送っていない」。`12` で配信終了
  - 備考：LINE 希望、停止（配信を止める）、再開日、詰まりが多い、など
- 保存は UTF-8（Excel で開くなら BOM 付き。見本がその形です）。
- 入れてはいけない場所：git（commit・issue・PR・タグ）、公開ページ、スクリーンショット、Claude Code への指示文（予約タスクはファイルを自分で読みます。中身を貼らない）。
- `log/` も git 管理外です。報告の1行に顧客名などが入っていたら「（顧客名）」に置き換えてから写します。
- 置き場：主担当と承認者の PC の `bootcamp/drills/` 直下。2人の間の受け渡しは、社内の共有フォルダ（外部に公開しないもの）で。メール添付やチャットに貼らない。
- 保持：12週の配信終了＋3か月の伴走が終わったら、その行を消す（案）。
- もし git に入ってしまったら：push 前なら `git rm --cached recipients.csv` で外す。push 後は履歴からも消す必要があるので、すぐ五味田さんに連絡し、消し方は Claude Code に頼む（決めるのは人）。

## 予約タスクは候補と下書きまで。push と送信は人

- 文面は `tools/scheduled_tasks.md`。金曜9:00「候補生成と該当週の差し替え案」、月曜8:00「配信下書き作成」。
- どちらも push しない・送信しない・名簿を書き換えない。作るのはファイルと下書きまで。
- PC が起動していて Claude Code が開いているときに動きます。動かなかった週は、上の手動手順で同じことをします。
- 初回は文面を貼って手動で一度動かし、できたものを見てから登録します。
- 費用：金曜の言い換え案は gpt-6-astra を1回呼びます（候補 最大48件、入力 約3〜4万字。初回はさらに多い）。初回実行後に OpenAI の使用量画面で1回分の金額を見て、この行に書きます（目安：＿＿円／回、五味田さんの API キー）。月の上限（＿＿円）を決め、超えたら `--no-llm` で回します。GitHub Pages と Claude Code の予約タスクに追加費用はありません（五味田さんの契約内）。
