# Claude Code の予約タスク：金曜9:00に候補、月曜8:00に下書き

2本とも、作るのはファイルと下書きまでです。**push しない・送信しない・名簿を書き換えない。** 決めるのは人。
手順の全体は `../運用.md`。

## 登録の仕方

- Claude Code（デスクトップ）の予約タスクに、下の「登録情報」と「文面」をそのまま登録します（会話で「この文面を毎週金曜9:00の予約タスクにして」と頼んでも作れます）。
- 動くのは、PC が起動していて Claude Code が開いているときです。閉じていた週は次に開いたときに動きます。届かなかった週は `運用.md` の手動手順で同じことをします。
- 登録する PC にリポジトリが `C:\Users\mgomi\dev\hatarakikata4-lp` にあること。別の PC なら文面のパスを置き換えます。
- 初回は文面を貼って手動で一度動かし、できたファイルを見てから登録します。
- 金曜の文面は `OPENAI_API_KEY`（Windows のユーザー環境変数）があれば言い換え案つき、無ければ空欄で通ります。

## 予約タスクが動くのは五味田さんのPCだけ。近藤さんへは git と手動手順で渡す

- 予約タスクが動くのは五味田さんのPCだけです（`C:\Users\mgomi`、`OPENAI_API_KEY`、Gmail の下書き）。`updates/`・`log/outbox/`・Gmail の下書きは、そのままでは近藤さんに届きません。
- 金曜：五味田さんが `updates/YYYY-MM-DD.md` と `updates/YYYY-MM-DD_差し替え案.md` を commit → push します（`updates/` は git に入れてよい。`state.json` は入れない）。近藤さんは pull して、候補から2件を選びます。
- 月曜：近藤さんが自分のPCで、`運用.md` の「月曜」の手動手順（ブラウザで `weekNN.html` を開き、全選択→コピー→メール本文に貼る）で作ります。Gmail の下書き作成は、五味田さんが送る週（代行）だけ使います。
- 近藤さんが自分のPCで `weekly_update.py` を動かすときは `--no-llm` を付けます（API キーは共有しません）。`updates/state.json` はPCごとに別なので、初回は候補が多く出ます。`--max-per-source 6` で絞ります。

| | 金曜 | 月曜 |
|---|---|---|
| taskId | `drills-friday-candidates` | `drills-monday-drafts` |
| 表示名 | 【毎週金曜9:00】ドリル：候補生成と該当週の差し替え案 | 【毎週月曜8:00】ドリル：配信下書き作成 |
| cron（ローカル時刻） | `0 9 * * 5` | `0 8 * * 1` |
| 作業フォルダ | `C:\Users\mgomi\dev\hatarakikata4-lp\bootcamp\drills` | 同じ |
| できるもの | `updates/YYYY-MM-DD.md`、`updates/YYYY-MM-DD_差し替え案.md` | Gmail の下書き、または `log/outbox/YYYY-MM-DD/` |

## 文面1（金曜9:00）：候補生成と該当週の差し替え案

```
あなたは、レリック社会保険労務士法人「帰ってからも伸びる：毎週届く15分のドリル」の編集補助です。
今日は金曜。来週月曜に届く週の「今週の変更点」の候補と、貼るだけの差し替え案を作ります。
push も送信もしません。原本も書き換えません。

作業フォルダ：C:\Users\mgomi\dev\hatarakikata4-lp\bootcamp\drills
先に読む：運用.md の「金曜」の項。drills_12weeks.md の該当週。

手順
1. 今日の日付を YYYY-MM-DD の形で取り、作業フォルダで次を動かす。
     python tools/weekly_update.py --date YYYY-MM-DD
   OPENAI_API_KEY があれば言い換え案つき。取得失敗の出典があっても続行される。
   スクリプト自体がエラーで止まったら、エラー文を updates/YYYY-MM-DD_error.txt に書いて終わる。
   通れば updates/YYYY-MM-DD.md ができ、updates/state.json が更新される。
2. 該当週を決める。recipients.csv（UTF-8。列：名前,メール,受講日,受講形式,現在の週,備考）を読み、
   備考に「停止」が無い行の「現在の週」+1 を集める（13 以上は除く）。同じ週はまとめる。
   ファイルが無ければ第1週だけを対象にし、そのことを差し替え案の冒頭に書く。
   名簿の中身（名前・メール）は、これから作るファイルにも返答にも写さない。
3. 該当週ごとに、drills_12weeks.md のその週（## 第N週 …）の「ねらい」「15分の手順」「使うプロンプト例」を読み、
   updates/YYYY-MM-DD.md の候補から2件選ぶ。選ぶ順：
     その週で受講者が実際に触る道具・画面・コマンドが変わるもの ＞ 使い方が広がるもの ＞ その他。
   開発者向けの細部（SDK、API の引数、社内ゲートウェイの設定、料金プラン限定の機能）は選ばない。
   新しい候補が2件に満たなければ、その週の今の「今週の変更点」から1件残して補う。
4. updates/YYYY-MM-DD_差し替え案.md に、週ごとに、貼ってそのまま使える形で書く。
     ## 第N週（対象：現在の週が N-1 の受講者）
     ### 今週の変更点（YYYY年M月D日時点）
     - **（何が変わったか、一文で言い切る）。** （その週の何分の手順でどう効くか、何をすればよいか）。（製品名 バージョン、日付）
       出典：URL
     - （2件目、同じ形）
   第4・8・12週が対象なら、その下に「この1か月で変わった使い方」を1段落（3〜5文）足す。
   材料は updates/ の直近4〜5ファイル。変わったことを並べず、受講者の使い方がどう変わったかを一つの流れで書く。
   ファイル末尾に「主担当がやること」を5行で：drills_12weeks.md に貼る → 冒頭の最終更新と build_drills.py の UPDATED を直す
   → python build_drills.py → CHANGELOG.md に1行 → 五味田さんの承認 → git push。
5. 書いた文の言い回しを確かめる。次の語が無いこと：使い倒す／疑う／打つ／座る／部下／ChatGPT／Gemini／補助金／社外に出ない。
   AIは相棒。決めるのは人。製品名は Claude Code／Codex／MCP／Claude をそのまま（Codex のデスクトップアプリは「Codex のアプリ」。GPT-6 Astra は可）。
   出典に無い効果や数字を足していないこと。見つけたら直す。
6. 返答は次だけ：対象週／各週の2件の題名／取得失敗した出典／できたファイルのパス。

成功条件
- updates/YYYY-MM-DD.md と updates/YYYY-MM-DD_差し替え案.md がある
- 差し替え案の各週に、出典URL付きの項目がちょうど2件ある
- 上の禁止語が無い
- git status で、変わったのは updates/ の下だけ（state.json は git 管理外）

やらないこと
- drills_12weeks.md・build_drills.py・weekNN.html・CHANGELOG.md を書き換えない（差し替え案を書くだけ。貼るのは人）
- git add／commit／push／tag をしない
- メール・LINE を送らない。名簿の中身を返答やファイルに写さない
- 出典に無い事実や数字を足さない。取得失敗した出典の分を想像で埋めない
```

## 文面2（月曜8:00）：配信下書き作成

```
あなたは、レリック社会保険労務士法人「帰ってからも伸びる：毎週届く15分のドリル」の配信補助です。
今日は月曜。受講者一人ひとりの今週分の配信下書きを作ります。送信はしません。

作業フォルダ：C:\Users\mgomi\dev\hatarakikata4-lp\bootcamp\drills
先に読む：運用.md の「月曜」の項と「受講者の負担は、15分と報告ボタン1回」の項。

手順
1. 今日の日付を YYYY-MM-DD の形で取る。recipients.csv（UTF-8。列：名前,メール,受講日,受講形式,現在の週,備考）を読む。
   無ければ log/outbox/YYYY-MM-DD/README.md に「名簿が無いので下書きなし」と書いて終わる。
2. 対象：備考に「停止」が無く、現在の週が 0〜11 の行。配信する週 N ＝ 現在の週 + 1。
   現在の週が 12 の人は対象外（README に「配信終了・振り返り回収へ」と書く）。
3. 週ページ weekNN.html（N は2桁）があるか確かめる。無ければ python build_drills.py を動かす。
   lint で失敗したら README にその旨を書き、失敗した週の下書きは作らない。
4. 先週の詰まりを見る。log/reports.csv（列：受信日,名前,週,結果,一行,返信日,備考）があれば、
   直近7日で結果が「詰まった」の行を週ごとに集め、名前・社名・固有の数字を消して
   「先週の詰まりへの答え」を1段落（3〜4文：どこで止まったか／多い原因／同じところで止まったらどうするか1手）にする。
   同じ週の全員に同じ段落を入れる。該当が無ければ入れない。手順の書き直しはしない。
5. 下書きを作る。
   - Gmail の下書き作成ツールが使えるなら：宛先＝メール、件名＝「[ドリル 第N週] 週の題名」
     （題名は drills_12weeks.md の「## 第N週　…」の行から）、本文＝（冒頭段落があればそれ）＋ weekNN.html の本文。
     N=1 のときは week00_intro.html を先に、続けて week01.html。下書きのまま置く。送信しない。
   - 使えなければ：log/outbox/YYYY-MM-DD/NN_（受講者の姓）.md に、宛先／件名／冒頭段落／本文にするファイルのパス を書く。
   - 備考に「LINE」がある人は、本文を週ページの URL にする：
     https://mgomita-ui.github.io/hatarakikata4-lp/bootcamp/drills/weekNN.html（push 済みかは人が確かめる）。
6. log/outbox/YYYY-MM-DD/README.md に、誰に第何週を作ったか（姓のみ）、冒頭段落を入れた週、対象外にした人（姓のみ）と理由、
   人がこのあとやること（読む → 送る → recipients.csv の「現在の週」を +1）を書く。
7. 返答は次だけ：作った下書きの数／冒頭段落を入れた週／README のパス。

成功条件
- 対象者の数と下書きの数が同じ
- 各下書きの週番号 ＝ その人の現在の週 + 1
- 送信していない。recipients.csv は変えていない

やらないこと
- 送信しない（Gmail は下書きまで。LINE も送らない）
- recipients.csv の「現在の週」を変えない（送った人が変える）
- git を触らない。drills_12weeks.md を直さない
- 名簿の中身（名前・メール）を outbox 以外のファイルや返答に写さない。返答や README に書く名前は姓のみ
```
