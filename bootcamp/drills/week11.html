第11週

小さなツールを、同僚が使える形に

1回15分。頼む → 動かす → 確かめる → 直す。決めるのは、あなた。

ねらい

研修の約束②にある「必要な仕組みを、その場で作る」の続き。作ったものを、翌日の仕事で同僚が使える形にします。第3週の見積スクリプト、または第9週の納期リスクを、AI を使ったことのない同僚が「読んで動かせる」形にします。README 3行、入力ファイルの置き場所、エラーのときの表示。作るのは AI、確かめるのは自分、渡すのは翌日。

15分の手順

時間すること
0〜2分claude で、渡すツールを1つ選ぶ（見積スクリプト or 納期リスク）
2〜7分下のプロンプトで、README・置き場所・エラー表示を整えてもらう
7〜11分確かめる：別のフォルダにコピーし、README だけを見て自分で動かす
11〜13分直す：README で詰まった箇所を直してもらう。Codex に「詰まりそうな点3つ」を予想させる
13〜15分記録とダッシュボード（2分）：drill_log.md に1行。渡す相手と日を決める。ダッシュボードに1枚足す（下記）

使うプロンプト例

このフォルダの見積スクリプトを、AI を使ったことのない同僚が使える形にして。
① README.md（3行：何ができる・どこにファイルを置く・どう動かす）
② 入力ファイルの置き場所を「input」フォルダに固定
③ エラーのときは、原因と直し方を日本語で1行表示
先に、変える点を箇条書きで言ってから直して。

Codex に（見直し）：

README.md とスクリプトを読んで、初めての人が詰まりそうな点を3つ予想して。直すかは私が決める。

ダッシュボードに1枚足す

その週の結論と数字が、ダッシュボードの「引継ぎと90日」に入ります。

今週（第11週）のドリルの結果を、ダッシュボードに1枚足して。

作る前に、次の4つを先に私に見せて、私の答えを待って。
① 結論（1〜2文）
② 数字（4つまで。どのファイルのどの行・どの列から取ったか。計算した数字は計算式も）
顧客名・個人名は、前提メモの「名前の扱い」に従う。
③ 次の一手（何を、誰が、いつまでに）
④ 人が決めること（1つの問い）と、いまの状態（未決・決定・保留）
専門家（社労士・税理士・弁護士）に確かめた方がよい点があれば、それも1つだけ挙げて。無ければ挙げない。

私が「OK」と言ったら、ファイルを読み直さずに、見せた内容のまま、次の2つだけを行って。
・dashboard/data/w（2桁の週番号）-（今の日付と時刻 YYYYMMDD-HHMM）.js を新しく作る
・dashboard/index.html の「WEEKS:END」の行のすぐ上に、<script src="data/そのファイル名"></script> を1行足す
既にあるファイルは書き換えない・消さない。同じ週をやり直したときも、新しい日時のファイルを足す（新しいものが表示される）。

ファイルの形（この形のまま埋める）
DASH.add({
  week: 11,
  date: "YYYY-MM-DD HH:MM",
  practice: （練習データなら true、自社の数字なら false）,
  title: "",
  conclusion: "",
  numbers: [ { label: "", value: 数字, unit: "", note: "" } ],
  source: "",
  next: { action: "", owner: "", due: "" },
  decision: { status: "（未決／決定／保留）", question: "", note: "" },
  expert: { topic: "", question: "" }
});
専門家に確かめる点が無ければ、expert の行は入れない。
